# Lisjaki content updates

Run from the Lisjaki repository root. Read `AGENTS.md` for project boundaries and `git status --short` to identify unrelated changes. Use `npm run content -- help` for commands. Editable records live in `src/data/content/*.json`; existing `src/data/*.ts` are adapters. The tournament uses separate D1 persistence and is outside this workflow.

For questions such as “What updates can we make to the data on the page?”, review current content, run `npm run content -- check` when dependencies are installed, and use a fresh league fetch or `league sync --dry-run` to identify available standings/fixture changes. Summarize concrete opportunities and missing user inputs. This is a read-only review: do not apply changes or publish unless requested. Do not present the saved test fixture as current league data.

Translate the user's natural language, attachments and screenshot lineups into structured inputs. Users do not need to provide JSON. Read [inputs](references/inputs.md) only for the relevant operation. Save temporary inputs outside the repository. Prefer one `batch` for related actions; its entire state is validated before writes. Use `--dry-run` when useful for inspecting large imports.

- Matches: resolve actual attendees, honor explicit absences, distinguish home/away scores, and identify the existing fixture by stable ID. Ask for missing final scores or ambiguous player identity; do not guess. Corrections use the same `match upsert`. Each goal is one scorer event. Match data already drives statistics. Manual writes mark the result as club-confirmed; league sync preserves it and its lineup.
- League: `standings sync` fetches the configured official group. `league sync` updates standings and fixtures/results together. Do not calculate the whole table from Lisjaki-only match history. An HTML snapshot supplied through `--html` must be freshly fetched from the configured season URL; the test fixture is not a current data source. `asOf` means the date the source was checked, not the latest match date. Report source disagreements; retain confirmed club results. If a fixture disappears from the source, inspect it rather than deleting it blindly.
- News: draft concise Slovenian club copy from provided facts and verified match records. Follow [editorial conventions](references/editorial.md). Do not invent quotes, tactical narratives, attendees, first-goal claims or dates. A missing photo can use the repository club logo temporarily if the user accepts it; preserve the appropriate contain display. New articles use supplied repository media, or `imageSource` to copy a supplied local cover without creating an album. Specify `matchId` for match reports and `gallerySlug` for related albums. Article/album auto-linking applies when their slugs match, or through explicit links.
- Photos: look first in `~/Pictures/lisjaki`, with one source folder per event. Inspect candidate photos before choosing a cover or classifying/reordering them. `gallery import` copies selected files with content-hashed names, leaves originals untouched, and preserves explicit order. Its `order` lists every selected filename; `last` moves selected files to the end. Existing albums can use `gallery reorder`. Use captions/alt text based on visible evidence. Use the CLI to copy media rather than modifying source originals.
- Roster: `roster upsert` retains player IDs and updates names/numbers; aliases may resolve familiar shorthand but must be unambiguous. `season set` activates configured season/group/source; include `league sync` in the same batch when possible. Prior seasons remain available.

After a batch, inspect notices and warnings. Fix broken media, unknown IDs and inconsistent scores. An incomplete historical scorer list or large preserved original can be disclosed without fabricating data. The current historical incomplete scorer list is match 6468; one older article uses external Unsplash media. Neither should silently become a new default.

Run `npm run content -- verify` once per finished batch; it performs content audit, behavioral tests, production build and diff check. Lint changed TS/TSX separately when changing implementation. A normal content update requires no dependency installation or tournament tests. Dependency changes require clean `npm ci`. Tournament/API changes require the checks in `AGENTS.md`.

Show the user a compact summary: match/result changes, standings check date and position, articles/albums, warnings, verification, and deployment status. If publishing was requested, proceed under that authorization. Otherwise leave changes local. A skill invocation does not independently authorize publishing. The `publish` command accepts an explicit content-only file list, checks the batch, commits and pushes the current branch; it rejects existing staged changes. On a feature branch a push does not publish production. Implementation changes need the normal Git workflow with an explicitly scoped commit.

For production, pushes to `main` trigger Pages. `npm run content -- deployment check --commit <full-sha>` confirms the served build marker; "pushed" and "deployed" are different states. If checking a deployment, retry at sensible intervals for up to five minutes and report pending/failed accurately. Do not install monitoring automations unless the user asks.
