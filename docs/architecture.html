Scope / whole website build + tournament server configuration

All pages share one Pages deployment.

The homepage, matches, statistics, news, galleries and tournament pages share the static build and CDN. The Functions and D1 connections shown here serve the tournament pages.

Deployment configuration: wrangler.jsonc → Pages output ./dist, database lisjaki-tournament, binding TOURNAMENT_DB.
Static generation ≠ live resultsBuilds generate the site shell. Public API reads fetch the current D1 document after loading.

Database lifecycleThe schema is a separate SQL migration. Deploying site assets does not replace tournament data.
Scope / tournament records used by /turnir + /turnir/vodenje

The tournament's stored data model.

D1 stores a complete JSON tournament document. Players, matches and scores here belong to the tournament. Solid connections mean stored containment/references; dashed connections mean calculations.

tournament_state · one active rowid = 'active' · state_json · revision · updated_at · updated_by
tournament_snapshots · latest 50 revisionsrevision · state_json · updated_at · updated_by
Stored versus computed: scores and team rosters are persisted. Appearance counts, personal points, rankings and analytics are recomputed.
What “points” meansA regular player receives their team's full preliminary score. Individual goals or who scored each rally are not tracked.
Write auditEach save records the server timestamp and authenticated Access email outside the tournament JSON.
RecoveryEvery retained snapshot contains the full state. No snapshot-restore interface exists yet.

Qualification: top 12 → four teams of three → two best-of-three semifinals → bronze match + final. Playoff scores decide advancement and medals; they do not add preliminary ranking points.
